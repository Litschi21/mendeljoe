# Wombat API Template (Debian)

A starting point for writing C++ programs against the [URC Wombat API], building
them in a container, and running them on a Wombat. Editor-agnostic: works with
VS Code (Dev Containers), CLion, or Neovim — anything that speaks clangd.

## How it works

- A single **amd64 build container** (`cross/Dockerfile`) carries both toolchains:
  native `g++` and the `aarch64` cross-compiler plus an arm64 sysroot.
- You set **`ARCH`** in `config.env` to choose the target:
  - `arm64` → cross-compiled for the Wombat.
  - `amd64` → native, for local testing.
- The editor / clangd runs natively in the container, so IntelliSense is fast;
  only the produced binary is arm64.

The Wombat API headers come from the `liburc-wombat-api-dev` package installed in
the container — they are **not** vendored into this repo. IntelliSense finds them
via `compile_commands.json` (generated by meson, symlinked to the repo root by
`scripts/build.sh`).

## Quick start

1. Edit `config.env` — at minimum set `TARGET_HOST` (your `user@wombat`) and
   `PROGRAM_NAME`. Leave `ARCH=arm64` to build for the Wombat.
2. Open the folder in your editor:
   - **VS Code:** "Reopen in Container" (Dev Containers extension). Build deps,
     clangd, and the cross toolchain are all set up automatically.
   - **CLion:** add the `cross/Dockerfile` as a Docker toolchain.
   - **Neovim / other:** build the image and develop inside it
     (`docker build -f cross/Dockerfile -t wombat-dev .`), or run clangd against
     the generated `compile_commands.json`.
3. Build, upload, and run:

   ```sh
   scripts/full-cycle.sh        # build -> upload -> run
   ```

   Or step by step:

   ```sh
   scripts/build.sh             # compile for $ARCH
   scripts/upload.sh            # scp the binary to the Wombat
   scripts/run.sh               # run it over ssh
   scripts/clean.sh             # remove build dirs
   ```

## Configuration (`config.env`)

| Variable       | Meaning                                              |
| -------------- | ---------------------------------------------------- |
| `ARCH`         | `arm64` (Wombat) or `amd64` (local testing)          |
| `PROGRAM_NAME` | Output binary name                                   |
| `TARGET_HOST`  | `user@host` of the Wombat for upload/run             |
| `TARGET_DIR`   | Remote directory to copy the binary into and run from |
| `SSH_OPTS`     | Extra ssh/scp options, e.g. `-i $HOME/.ssh/key` (use `$HOME`, not `~`) |

## Layout

```
config.env            your settings (the only file you normally edit)
meson.build           build definition
meson.options         exposes program_name
src/main.cpp          the tutorial program
include/              your own headers (on the include path)
cross/Dockerfile      build container (native + aarch64 cross)
cross/arm64-cross.ini meson cross-file (internal; driven by ARCH)
cross/apt-setup.sh    adds the URC apt repo + installs build deps
scripts/              build / clean / upload / run / full-cycle
.devcontainer/        VS Code Dev Container config
```

## Notes

- Reading sensors does not require `acquire_control()`; that is only needed to
  drive motors/servos (it takes the hardware lock and starts a heartbeat).
- The Wombat daemon socket defaults to `/run/wombat/api.sock`.
- On NixOS, Dev Containers work as long as the Docker daemon is enabled and your
  user is in the `docker` group; the toolchain lives inside the container.
