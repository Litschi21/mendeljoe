# Wombat API Template (Debian)

A starting point for writing C++ programs against the [URC Wombat API], building
them in a container, and running them on a Wombat. Editor-agnostic: works with
VS Code (Dev Containers), CLion, or Neovim — anything that speaks clangd.

## How it works

- A single **amd64 build image** (`cross/Dockerfile`) carries both toolchains:
  native `g++` and the `aarch64` cross-compiler plus an arm64 sysroot. It is
  **built and pushed by CI** (`.forgejo/workflows/image.yaml`) to the registry —
  you just pull it, no local image build.
- You set **`ARCH`** in `config.env` to choose the target:
  - `arm64` → cross-compiled for the Wombat.
  - `amd64` → native, for local testing.
- The editor / clangd runs natively in the container, so IntelliSense is fast;
  only the produced binary is arm64.
- The `scripts/` run **inside** the image: on the host they transparently
  `docker run` the image; inside the VS Code dev container they run natively.

The Wombat API headers come from the `liburc-wombat-api-dev` package baked into
the image — they are **not** vendored into this repo. IntelliSense finds them
via `compile_commands.json` (generated by meson, symlinked to the repo root by
`scripts/build.sh`).

## Access

The image lives in a **private** registry. Log in once (any Docker/Podman host):

```sh
docker login git.robo4you.at
```

Username is your Forgejo name; password is a **`read:package`** token from
Forgejo → *Settings → Applications*. After that, `docker pull`, the scripts, and
VS Code "Reopen in Container" all work. The token is only stored by `docker
login` (`~/.docker/config.json`) — never put it in `config.env`.

## Quick start

1. Edit `config.env` — at minimum set `TARGET_HOST` (your `user@wombat`) and
   `PROGRAM_NAME`. Leave `ARCH=arm64` to build for the Wombat.
2. Open the folder in your editor:
   - **VS Code:** "Reopen in Container" (Dev Containers extension) — pulls the
     prebuilt image; clangd and the cross toolchain are ready immediately.
   - **CLion:** add the pulled image as a Docker toolchain.
   - **Neovim / other:** just run the `scripts/` on the host — they auto-run
     inside the image. For clangd, point it at the generated
     `compile_commands.json` (or run clangd inside the image).
3. Build, upload, and run:

   ```sh
   scripts/deploy.sh            # build -> upload -> run
   ```

   Or step by step:

   ```sh
   scripts/build.sh             # compile for $ARCH
   scripts/upload.sh            # scp the binary to the Wombat
   scripts/run.sh               # run it over ssh
   scripts/clean.sh             # remove build dirs
   ```

## Configuration (`config.env`)

| Variable       | Meaning                                                |
| -------------- | ------------------------------------------------------ |
| `ARCH`         | `arm64` (Wombat) or `amd64` (local testing)            |
| `PROGRAM_NAME` | Output binary name                                     |
| `TARGET_HOST`  | `user@host` of the Wombat for upload/run               |
| `TARGET_DIR`   | Remote directory to copy the binary into and run from  |
| `SSH_OPTS`     | Extra ssh/scp options, e.g. `-i $HOME/.ssh/key`        |
